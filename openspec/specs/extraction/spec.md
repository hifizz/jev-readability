# v0.1 内容提取规范

## 目标
把 HTML / Document 中的正文定位做成可组合 JS/TS 库：DOM 切块、JEV 结构化判别、代码从原文重建输出。独立于 ThreadChat。本次授权交付到 hifizz/jev-readability，并准备公开 npm 包；没有完成 registry 认证时不得宣称发布成功。

## 行为要求

### 原文与分块
- 给定标题、代码、列表、表格及混合嵌套文本，切块后顺序与文档一致，无父子重复、无直接文本遗漏。
- 短标题和高链接密度的文档引用列表仍可成为候选，不因长度/密度被硬删除。
- 输入 Document 必须克隆；不能在宿主网页上删除节点。
- 超过大小、深度或候选数限制时明确报错，不静默截断。

### 判别协议
- 真实 JEV 使用原生 `state` + `questions` API。
- 每块的 noul 问题必须在 instructions 中引用目标 ID；读取 `noul`，不读取不存在的 probability 字段。
- 同一批共用 state；每个问题独立判别。超出内部预算后分批，记录请求数与采样。
- 模型只输出判断，不能提供可覆盖原文的 text/html/markdown。

### 不确定与失败
- 保留原始概率，不把局部角色 confidence 当作整页准确率。
- 显式标记不确定块；错误默认抛出，降级必须用户显式开启。
- 用户取消和超时不能变成一次“成功的模型提取”。
- API 重试必须有限，响应校验和输入校验必须在普通代码中执行。

### 数据与展示
- API key 只在服务端。演示服务器只监听 loopback；限制请求体、并发，检查 Host / Origin / session token。
- 输出用允许列表重建；演示页以纯文本显示，不运行原始 HTML。
- JEV 和本地规则的结果在 method、UI、usage 中明确区分。

### 安装与发布
- ESM 根入口、/jev、/node 与类型声明可导入。
- GitHub 源码安装通过 prepare 自动构建；npm 包包含 dist 与可执行 CLI。
- 发布前检查类型、编译和单元测试；包文件白名单排除密钥与本地环境。
- 首次 npm 发布需要维护者认证；后续 Trusted Publishing 必须先在 npm 配置授权。

## 不包含
真实网页 benchmark、动态网页抓取/渲染、浏览器扩展发布、服务端多租户鉴权、收费/计费产品、替代成熟 HTML sanitizer 的承诺。

## v0.2 验证重点
首先建立真实网页标注集和 Readability 对照，再优化长块、分块粒度、阈值与批次；未测量前不宣传准确率或速度优势。
